# QC Academy · 백오피스 실습형 튜토리얼

신입 QC 매니저를 위한 React + Vite 기반 게임형 실습 목업입니다. 설명만 넘기는 슬라이드가 아니라 **실제 키보드와 텍스트 드래그 결과를 검사하여 다음 미션을 여는** 13단계 튜토리얼입니다.

첨부 업무 가이드 **1~7페이지**의 워크스페이스 → 기관 선택 → OP 결과 파일 QC → 문항 검토 → QC 완료 → 파일 목록 복귀 흐름을 재구성했습니다. 추가 요청한 기본/심화 검출과 QC스페이스 과업 연동을 포함하며, PDF 8페이지 이후의 취합·딥셀렉은 포함하지 않습니다. PDF 자체나 실제 지원자 데이터를 저장소에 포함하지 않습니다.

## 설치 및 실행

Node.js **20.19 이상 또는 22.12 이상**의 Vite 지원 버전을 사용하세요. 개발·검증 환경은 Node.js 24입니다.

```sh
npm ci
npm run dev
```

브라우저에서 Vite가 출력하는 주소를 여세요(기본 포트 5173). 서버, DB, 로그인, API 키, `.env` 설정은 필요 없습니다.

```sh
npm run build     # dist/ 생성
npm run preview   # 프로덕션 빌드 확인, 기본 포트 4173
```

## 실습 방법

1. **튜토리얼 시작하기** → 왼쪽 **워크스페이스** → 다음 단계 → **한빛공사** → 다음 단계 → 파일 A **QC하기**.
2. **E 키를 누른 채** `한빛대학교`를 드래그합니다. 키 입력만으로는 완료되지 않습니다.
3. **출신지역** 카테고리 토글을 켠 후 키 없이 `서울`을 드래그합니다.
4. **D 키를 누른 채** `한빛대학교` 전체를 드래그하여 취소합니다. `서울` 검출은 남습니다.
5. 파일 A에서 E + 드래그로 `김하늘`을 검출합니다. 파일 B에서 D + 드래그를 시도하면 취소 제한 사유가 나오고 검출은 유지됩니다. 파일 A로 돌아와 취소합니다.
6. 파일 A에서 다시 `김하늘`을 검출 → **QC스페이스** → 파일 A **과업 상세** → D + 드래그로 취소합니다.
7. 워크스페이스의 파일 A로 돌아가 동기화를 확인합니다. **1·2·3번 문항**을 확인하고 **검토 완료**를 눌러 QC 완료 상태로 파일 목록에 복귀합니다.
8. 단계별 **다음 단계**는 올바른 행동과 결과를 확인한 뒤에만 활성화됩니다. 이전 단계로 돌아가면 해당 단계의 실습 스냅샷을 복원합니다.

본문 안에서 정확한 범위를 선택하세요. 키는 마우스를 누르기 전부터 드래그가 끝날 때까지 유지해야 합니다. 카테고리가 켜져 있으면 E 검출에도 해당 카테고리를 사용합니다. 토글을 다시 누르면 해제됩니다. 기존 검출과 겹치는 추가 검출은 거부하고, D 취소는 기존 검출의 **전체 범위가 정확히 일치하는 단일 내역**만 처리합니다. 잘못 검출한 경우 D로 취소한 후 다시 시도할 수 있습니다.

## 구현 내용

- 관리자형 사이드바, 워크스페이스 기관 검색, 파일 목록 및 QC 상태
- 자기소개서 본문, 문항 버튼, 선택 파일과 카테고리 상태
- 말풍선 가이드, 대상 강조, 성공·실패 알림, 진행률 및 완주 배지
- E + 드래그 / 카테고리 + 드래그 검출, D + 드래그 취소
- 검출별 ID, 실제 텍스트, UTF-16 시작·끝 위치(끝 제외), 카테고리, 원본 파일 ID, 활성/취소 상태와 이력
- 다른 파일에서는 취소 제한, 원본 파일에서만 취소
- 검출이 있는 파일의 과업 자동 생성, QC스페이스와 워크스페이스의 공유 상태
- 전체 / 기본 검출 / 심화 검출 / QC스페이스 기능별 재시작과 데이터 초기화
- 브라우저 localStorage에 진행 및 검출 이력 저장, 새로고침 후 복원
- 좁은 화면 레이아웃과 모션 감소 설정 지원. 키보드·마우스가 있는 데스크톱 사용을 우선합니다.

## 테스트

```sh
npm test             # 데이터 모델 및 범위·원본 파일 규칙 6개 테스트
npm run build        # Vite 프로덕션 빌드
npm run test:e2e     # Chromium 실제 조작 시나리오
npm run format:check # 코드 형식 확인
```

브라우저 테스트는 시스템 `/usr/bin/chromium`을 우선 사용합니다. 시스템 Chromium이 없는 환경에서는 `npx playwright install chromium`으로 Playwright 브라우저를 설치하세요. 다른 시스템 브라우저는 `CHROMIUM_PATH`로 경로를 지정할 수 있습니다. Linux에서 시스템 라이브러리가 필요하면 Playwright 공식 설치 명령 `npx playwright install --with-deps chromium`을 사용하세요.

브라우저 시나리오는 전체 13단계 완주, 키 입력만으로 미완료, 수정키 없는 드래그 거부, 부분 범위 취소 거부, 다른 파일 취소 제한 시 상태 보존, 원본 파일 취소, QC스페이스 취소 동기화, 문항 검토/QC 완료, 잘못된 카테고리, 이전 단계, 기능별 재시작, 새로고침 복원, 390px 화면의 가로 넘침을 검증합니다. 화면 캡처는 테스트 실행 시 `test-results/`에 생성됩니다.

## 구조 및 확장

```text
src/
  App.jsx          화면 전환, 실습 상태, 실제 DOM 선택 범위 처리
  components.jsx   가이드·재시작 다이얼로그·검출 텍스트 렌더링
  model.js         가상 데이터, 검출/취소 규칙, 미션 정의와 초기 상태
  styles.css       반응형 관리자 UI와 미션 강조 스타일
  main.jsx         React 진입점
 tests/
  model.test.js    데이터 무결성 테스트
  tutorial.spec.js 실제 키보드·마우스 브라우저 테스트
```

검출 상태는 App의 단일 상태에서 관리합니다. 화면별 복제본을 만들지 않으므로 파일·메뉴 이동에도 원본 파일 ID가 유지됩니다. 원본 파일과 무관하게 공통 지원자 본문 위에 활성 검출이 표시되며, 취소 시 ID를 기준으로 한 내역만 갱신합니다. 취소된 내역과 파일별 과업은 이력으로 유지됩니다.

## 목업의 범위와 제한

- 한 기관, 파일 A/B, 한 명의 가상 지원자와 공통 자기소개서로 구성한 독립 데모입니다. 문항 탭은 질문 제목과 확인 상태를 전환하며, 범위 실습용 본문은 공통으로 유지합니다.
- 실제 API·DB·로그인·운영 데이터 연결, 파일 업로드·다운로드, PDF 8페이지 이후 기능은 범위에서 제외했습니다.
- 데이터는 현재 브라우저에만 저장됩니다. 다른 기기와 서버로 공유되지 않으며, 다시 시작하거나 브라우저 저장소를 삭제하면 초기화됩니다.
- 모바일 레이아웃은 제공하지만 E/D 실습은 물리 키보드와 마우스가 필요합니다.
